# Architecture

GOK-Pi automates battery charge/discharge. An agent runs next to each battery,
executes schedules, and optionally streams telemetry to a central control server
that hosts the web UI, generates price-based schedules, and relays commands.

```
┌─────────────┐           ┌──────────────┐           ┌─────────────┐
│   Agent     │◄─────────►│   Control    │◄─────────►│   Web UI    │
│  (device)   │ WebSocket │   server     │ WebSocket │  (browser)  │
└──────┬──────┘           └──────┬───────┘           └─────────────┘
       │ driver (HTTP / Modbus)  │ webhooks, REData prices, Brevo
       ▼                         ▼
   Battery                   evsys, REE, email
```

## Executables

| Command | Role |
|---|---|
| `cmd/gok` | Agent. Loads `config.yml`, runs one status poller plus a charge and a discharge controller per enabled battery, connects to the control server when `remote_control.enabled`, exposes Prometheus metrics when `metrics.enabled`. |
| `cmd/controlserver` | Central hub. Agent and UI WebSockets, REST API, config store with optimistic locking, price fetching and auto-schedules, energy session DB, email reports and connectivity alerts, evsys webhook receiver, serves the UI and `/downloads`. Configured by YAML (`-config`) or environment. |
| `cmd/agentupdater` | Compares the remote `VERSION` SHA-256 with the local binary, replaces it atomically, optionally restarts the agent service. |
| `cmd/essprobe` | Read-only Modbus diagnostic for Huawei ESS; see [huawei-integration.md](huawei-integration.md). |

## Agent

### Control loop

- `StatusPoller` (`battery/controller/poller.go`) is the single source of status
  per battery: one driver request per 10 s tick, fanned out to both controllers.
  After a few consecutive failures it publishes a nil status so controllers stop
  acting on stale data.
- `Controller` (`battery/controller/controller.go`) is parameterized by
  `Direction` (`ChargeDirection()` / `DischargeDirection()`): schedule filter,
  SoC stop condition and driver calls differ, the loop is shared.
- `ModeCoordinator` (`battery/controller/mode.go`) owns the manual/auto
  operating mode across both directions: the battery returns to auto only when
  neither direction is active.
- On startup `syncStateFromBattery` re-derives a running manual operation so a
  restart does not cancel it.

Commands: `CommandStart`, `CommandStop`, `CommandSetLimits`, `CommandForceMode`,
`CommandUpdateConfig`, `CommandResetGoal`. A manual start becomes an override
that bypasses schedule windows; an override sourced from the charger integration
also survives config pushes.

### Schedules

1. Start/stop times are parsed in the configured timezone; windows may span
   midnight (22:00 → 06:00); `24:00` is accepted as end of day.
2. `run_once` schedules record `GoalReachedTime` when the SoC limit is reached
   and are skipped until `stop_time` passes, then the goal clears for the next
   day. The goal lives in the schedule, so deleting a schedule removes it.
3. `Schedule.Validate` rejects zero-length windows.

Auto-schedules (`auto-*` names) are generated by the control server from
electricity prices and pushed to the agent as config.

### Worker lifecycle

`workerManager.Apply` (`cmd/gok/main.go`) diffs desired vs running batteries:
URL/token changes restart the workers with a new driver, schedule-only changes
send `CommandUpdateConfig`, new batteries get a poller plus both controllers.

### Shutdown and restart

Context cancellation stops controllers, pollers and the WebSocket client; a
WaitGroup waits for them. A remote `restart_agent` command exits with code 75
after the same graceful shutdown, so systemd brings the agent back.

## Battery drivers

Each vendor implements `driver.Driver` (`battery/driver/driver.go`):

```go
Status() (*entity.SystemStatus, error)
StartDischarge(power int) error
StopDischarge() error
StartCharge(power int) error
StopCharge() error
SwitchOperatingModeToManual(currentMode string) error
SwitchOperatingModeToAuto(currentMode string) error
```

Adding a driver:

1. Create `battery/driver/<name>/` implementing `driver.Driver`.
2. Call `driver.Register("<name>", constructor)` in its `init()`.
3. Blank-import `_ "gok-pi/battery/driver/<name>"` in `cmd/gok/main.go`.
4. Add the matching `<option>` in `web/ui/src/components/config/BatteryConfigForm.tsx`.

The Sonnen driver maps these to `/status`, `/setpoint/{charge,discharge}/{W}`
and `/configurations?EM_OperatingMode=1|2`. Transient failures are retried with
backoff; 4xx responses other than 429 are not.

## Remote protocol

Agents connect to `/api/agent` with `X-GOK-Shared-Secret` and `X-GOK-Agent-ID`
headers; the UI connects to `/api/ui`, authenticated when `ui_username`/`ui_password`
are set (fail-open otherwise).
Read/write/ping deadlines are enforced on both sides.

| Direction | Messages |
|---|---|
| agent → server | `agent.hello`, `agent.heartbeat`, `agent.telemetry`, `agent.config`, `agent.log.response`, `agent.diag.response` |
| server → agent | `server.config.push`, `agent.command`, `server.log.request`, `server.diag.request` |

### Config synchronization

The UI edits an agent's batteries, schedules, charger links and email settings;
the control server stores them in its config store (`config_store` path) with a
`revision` for optimistic locking — stale saves are rejected. The update is
pushed to the connected agent, which merges it (preserving schedule goal state)
and persists it to its local `config.yml`. Agents that reconnect later receive
the latest revision; with no stored override the store is seeded from the
agent's own snapshot.

## Control server features

- **Prices and auto-schedules** — `pricefetcher` polls REData; `scheduler` picks
  windows; `autoschedule` turns them into schedules per battery with
  `auto_schedule` enabled, filtered by price limits (`/api/price-limits`).
- **Energy sessions and history** — charge/discharge sessions and telemetry
  history in the session DB (`/api/sessions`, `/api/history`).
- **Email reports** — see `CLAUDE.md` data flow §7; Brevo credentials in
  `email_provider`, recipients per agent.
- **Connectivity alerts** — `agentWatcher` emails once after 10 minutes offline
  and once on recovery.
- **EV chargers** — see [evsys-integration.md](evsys-integration.md).

## Metrics

`metrics/observers` updates Prometheus gauges and telemetry snapshots;
`metrics/server` serves `/metrics` on `metrics.bind:metrics.port` (default
`0.0.0.0:5001`). Gauges: `battery_RSoC`, `battery_USoC`,
`battery_RemainingCapacity_W`, `battery_Consumption_W`, `battery_Pac_total_W`,
`battery_BatteryDischarging`, `battery_BatteryCharging`,
`battery_BatteryOperatingMode`.
